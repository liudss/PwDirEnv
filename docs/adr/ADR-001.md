# ADR-001：RC 使用 PowerShell，不使用声明式配置

Status: Accepted

## Context

direnv 的核心价值在于配置文件是可编程脚本：用户可以写条件判断、调用外部命令、组合已有工具链。若把 `.envrc` 改造成 TOML/YAML/JSON 等声明式格式，会丧失这种可编程性，用户也需要学习新的 DSL。Windows 生态中 PowerShell 是系统原生脚本语言，拥有成熟的解析器、PSScriptAnalyzer、VS Code 扩展等工具链支持。

## Decision

项目配置文件必须是合法的 PowerShell 脚本，默认文件名为 `.envrc.ps1`。用户可直接使用 `$env:NAME = 'value'`、`Remove-Item Env:NAME`、条件判断、管道、模块、外部命令等正常 PowerShell 语法。明确拒绝声明式配置，也不兼容 Bash `.envrc` 语法。

## Consequences

- 用户无需学习新 DSL，任何 PowerShell 能力都可用于环境配置，可编程性得到完整保留。
- PowerShell 工具链（parser / linter / 编辑器）对 `.envrc.ps1` 开箱即用。
- 脚本是任意代码，必须配合内容哈希 trust 模型（见 ADR-005）防止"cd 进陌生仓库即执行代码"。
- 首版不自动执行 `.envrc`，避免误把 Bash 文件交给 PowerShell 解释。
