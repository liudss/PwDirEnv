# ADR-003：只把环境变量 patch 带回 Host

Status: Accepted

## Context

Evaluator 执行 RC 后会产生完整的 resulting environment。Host Shell 需要一种方式接收这些变化，但如果把"生成一段 PowerShell 源码再 `Invoke-Expression`"作为通道，就等于把任意代码执行权交还给了 native 输出，安全边界形同虚设，也无法表达"卸载/恢复"语义。

## Decision

Evaluator 与 Host 之间只传递结构化的环境变量 diff（EnvPatch：set/unset），以版本化 JSON schema（schema 1）编码。Host module 解析 JSON 后，用 `[Environment]::SetEnvironmentVariable(name, value, 'Process')` 逐键应用，禁止对 native 输出使用 `Invoke-Expression`。卸载时不是简单 unset，而是依据 Host 保存的 baseline 做 reconciliation，精确恢复进入项目前的值。

## Consequences

- 形成清晰的跨进程能力边界：native core 只能影响环境变量，无法向 Host 注入代码。
- 协议可独立版本化、可测试、可向前兼容（未来可扩展到其他 shell 前端）。
- diff + baseline 恢复模型让"离开目录精确还原"成为可验证的行为。
- Host 侧只允许修改 Process scope（见 ADR-006），边界职责进一步收窄。
