# ADR-007：dotenv 解析器在 PowerShell stdlib 内实现

Status: Accepted

## Context

SPEC §11 建议首版优先在 Rust core 提供 dotenv parser，由 stdlib helper 调 native command 或内置 bootstrap function。但 stdlib helper 运行在隔离 evaluator（pwsh 子进程）内、直接读写 `$env:` —— 若走 Rust parser，native core 必须把 pwdir.exe 自身路径（或专用解析子命令）传进 evaluator，helper 每次 `dotenv` 都要额外 spawn 一个子进程并把 KV 序列化回传。而 dotenv 在 RC 中是低频操作，这条跨进程链路的复杂度与收益不成比例。

## Decision

MVP 的 dotenv 解析器用 PowerShell 实现在 `evaluator/stdlib.ps1`（`Read-PwDirDotEnv` + `ConvertFrom-PwDirDotEnvLine`），语义遵循 SPEC §11 的最小子集：

- UTF-8（允许 BOM，读取时自动剥离）、CRLF / LF、空行与 `#` 注释行忽略；
- `export ` 前缀剥离（只认小写，与 sh 语义一致）；
- `KEY=value` / `KEY="value"`（最小 escape：`\"` `\\` `\n` `\r` `\t`，其余 `\x` 保留字面量）/ `KEY='value'`（全字面量）/ 无引号（`=` 后剩余文本，前后空白 trim）；
- 不做 command substitution 与 `${VAR}` 展开；
- key 不合规或无 `=` 的行静默跳过（lenient，确定性优先：引号不闭合时按字面量处理）；
- 默认不覆盖已存在的环境变量（direnv 兼容），`-Overload` 强制覆盖。

## Consequences

- 解析与 env 写入在同一 evaluator 进程内完成，无额外 spawn 与跨进程协议成本。
- 相对路径（默认 `.env`）以 project root 为基准解析，与其它 stdlib helper 语义一致。
- 与 SPEC §11「优先 Rust parser」是有意偏离；若 M6+ fingerprint 需要在 native 侧复用解析结果，回迁 Rust 实现时必须保持语义一致并补齐等价 fixture 测试（当前 fixture 见 `crates/pwdir-core/tests/stdlib_integration.rs`）。
