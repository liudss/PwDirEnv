# ADR-002：RC 在 child pwsh 中执行

Status: Accepted

## Context

如果在 Host Shell 中直接 dot-source `.envrc.ps1`，脚本可以随意修改 Host 的函数、alias、变量、prompt、已导入模块等任意状态，且这些副作用无法可靠撤销。要准确知道脚本"改了哪些环境变量"，也必须有一份执行前的快照作对比。

## Decision

`.envrc.ps1` 永远在一个隔离的 PowerShell evaluator 子进程（`pwsh -NoLogo -NoProfile -NonInteractive -ExecutionPolicy Bypass -File bootstrap.ps1`）中执行。Evaluator 继承 Host 当前 Process environment，加载 stdlib 后 dot-source RC，执行完毕后枚举子进程的 Process environment 作为结果环境。协议结果通过与 stdout/stderr 隔离的临时文件通道返回，避免脚本输出噪音污染协议。

## Consequences

- Host Shell 只接收结构化结果，RC 的函数 / alias / prompt / 模块 / 普通变量副作用被进程边界天然阻断。
- before/after 两份完整环境快照使 env diff 的计算变得简单、精确、可测试。
- 代价是每次完整 evaluate 都要冷启动一个 pwsh 进程（数百毫秒级），因此 hook 快速路径依赖 fingerprint 缓存（M6），未变化时不 spawn evaluator。
- 子进程必须加超时保护（默认 10s），防止 RC 死循环拖垮 prompt。
