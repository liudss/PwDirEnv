# ADR-006：Windows Process scope only

Status: Accepted

## Context

Windows 环境变量有三个 scope：Process、User、Machine。目录环境本质是"随当前 shell 会话生命周期存在"的状态：进入项目生效、离开项目还原。若写到 User/Machine scope，一个项目的配置会永久污染系统与其他会话，且"离开还原"语义根本无法实现。PowerShell 的 `EnvironmentVariableTarget.User/Machine` 写入还会触发广播并需要相应权限。

## Decision

PwDirEnv 的所有环境变量修改只使用 `EnvironmentVariableTarget.Process`（等价地 `Set-Item Env:NAME`）。Host module 明确禁止调用 User / Machine scope。子进程（evaluator、`pwdir exec` 的目标进程）的环境继承同样仅存在于其自身 Process scope，随进程退出消失。

## Consequences

- 目录环境随 shell 会话生灭，关掉终端即彻底还原，不存在跨会话残留。
- 不需要管理员权限，不会影响系统配置，降低误操作风险。
- 每个终端会话独立持有自己的 applied state，天然支持同一用户多 shell 并发处于不同项目。
- 明确的非目标：不提供把项目环境持久化到 User/Machine scope 的功能。
